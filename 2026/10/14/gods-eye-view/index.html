God’s Eye View：当真实世界被铺展在一颗可探索的三维地球上

项目地址：https://github.com/bilawalsidhu/gods-eye-view

如果把地球放进浏览器，并让它不再只是一张静态地图，会发生什么？

God’s Eye View 给出的答案，是一颗不断呼吸的三维地球。

飞机在天空中留下轨迹，船只沿着海面移动，卫星在轨道上划过，地震、火情、天气、道路交通、公共摄像头、公共交通、广播电台与太空任务等信号逐层浮现。它拥有一种近似电影中侦察座舱的视觉气质，却并不依赖神秘数据：项目聚合的是公开信号与公开或第三方数据源，并尝试将这些原本分散在不同位置的信息放到同一个可探索的地球中。

这是一款运行在浏览器中的间谍卫星模拟器，也是一套面向实时空间信息探索的开源客户端。

它让人从高空俯瞰，也让人能够一路靠近地面；让人查看全球尺度的动态，也让人可以锁定一架飞机、一艘船、一颗卫星、一处火情或一个摄像头位置。它不只是把数据叠在地图上，而是试图将地球塑造成一个可以观察、追踪、询问、标注、导演镜头并不断扩展的实时空间界面。

一颗不再沉默的地球

传统地图往往承担定位与导航任务。

God’s Eye View 则试图把地图变成一处持续变化的观察现场。飞行器应答机、船舶信标、轨道要素、地震仪、公共摄像头等公开信号本就不断产生信息，项目将它们放入同一个三维地球，让使用者能够在全球视角与局部视角之间穿梭。

它所呈现的不是一份固定答案，而是一个正在发生变化的场景。

天空中有正在移动的飞机。

海面上有航行中的船舶。

轨道上有被加载的卫星。

地面上有火情、道路交通、天气变化与公共摄像头相关信息。

这些图层各自拥有不同的节奏，却在同一个地球上汇合。于是，使用者不必只看某一类数据，而可以在飞行、航运、气象、基础设施、地面活动与太空任务之间切换视角。

God’s Eye View 希望提供的，正是这种从整体到局部的连续感。

像坐进一间虚构座舱，却面对真实信号

项目的视觉语言带有强烈的座舱感。

战术抬头显示界面、侦测覆盖层、传感器视觉风格、目标信息与三维地形共同构成了一种近似科幻电影的观察体验。它看上去像一个被设想出来的未来控制台，但其中的许多内容来自现实世界持续更新的数据流。

项目提供多种视觉风格，包括 CRT、夜视、热成像、黑白与雪景效果。

普通地球可以被重新着色。

天空、地形、城市与动态目标可以通过不同的传感器式视觉效果重新呈现。按下不同快捷键，整个实时地球便会切换到另一种观测氛围中。

这种变化并不只是外观替换。

当夜视、热成像与其他视觉样式叠加在实时图层之上时，地球仿佛获得了不同的观察方式。飞机、船只、道路、城市与地形依旧在那里，但它们被放进了另一种叙事框架：不是单纯观看世界，而是像坐在一间不断接收信号的观察室里理解世界。

从全球俯瞰，到锁定一架正在飞行的飞机

God’s Eye View 支持点击追踪目标。

当目标被选中后，镜头可以锁定它，界面能够显示元数据，并绘制逐渐消失的轨迹。对于已追踪的火情或船舶，项目还支持通过一次点击跳转到附近的实时摄像头。

这种追踪方式让静态的地球变得更具方向感。

你可以从全球尺度看见密集的空中与海上活动，也可以从其中挑出一个目标，交给镜头持续跟随。一个原本只是地球上小小符号的飞行器，能够成为观察的中心；一处火情不再只是地图上的标记，也可以成为进一步了解周边环境的入口。

项目还提供附近目标列表。以当前目标为中心，可以查看周边 250 千米范围内的相关对象，并在实时飞机之间切换。

当目光从宏大的地球缩向一个具体目标时，世界并不会失去背景。相反，附近的飞机、地形、城市、天气与其他图层会继续保留，使单个目标始终处在更广阔的环境之中。

驾驶舱视角：与真实航班一起穿越地形

驾驶舱模式是 God’s Eye View 最具沉浸感的能力之一。

它基于实时飞行数据构建。当使用者追踪一架飞机并进入驾驶舱模式时，镜头会跟随该目标移动，地形则保持在下方持续展开。项目描述这一体验时，强调的是与真实飞机一起飞越真实地形。

这不是传统意义上的飞行模拟器。

它不要求使用者操控飞行器，也不试图复刻完整的飞行操作流程。它更像是一种跟随式观察：现实中的飞行器正在移动，镜头选择与它同行。

在这一过程中，视觉样式也可以继续切换。夜视、热成像等效果不会因为进入驾驶舱视角而失去作用，反而会随着飞行过程一起移动。

驾驶舱还能够承载附近实时信号、区域新闻和当地天气等信息。项目中还提供可选的 WX 模式，用于呈现基于实际观测数据的体积云效果。

从轨道尺度拉近到一架飞机，再从飞机进一步进入贴近地形的镜头，God’s Eye View 让观察路径拥有了连续的纵深。

飞机不只是图标，也可以成为三维模型

在远距离观察时，飞行器可以以符号形式出现在地球上。

当镜头不断靠近时，God’s Eye View 会让被追踪的目标从符号切换为三维模型。项目列举了多类真实机型模型，包括 787、ATR-72、Citation、Bell 206 与 MQ-9。

这使飞行器在不同观察尺度下拥有不同形态。

远观时，它们是全球动态的一部分。

接近时，它们则成为更具体的三维对象。

项目还会在屏幕空间中为视野内目标提供边界框与标识信息。侦测覆盖层让观察界面更像一个持续读取场景的系统，而不是单纯摆放图层的三维地图。

目标在移动，信息也在出现。

世界不再只是被看见，而是被持续识别。

二十类图层，让地球拥有不同层次的现实

God’s Eye View 将数据图层分为移动、摄像头、基础设施、事件、天气与实用工具等类别。

在这颗三维地球上，使用者可以看到多种不同性质的空间信息。

飞行图层呈现实时飞机与航线历史。

军用飞行图层以琥珀色展示 ADS-B 军用航空交通。

船舶图层展示全球范围内的船只活动。

卫星图层提供分类着色的卫星目录，并能够加载更密集的 Starlink 卫星壳层。

地震图层呈现全球近二十四小时内的地震活动。

火情图层使用 NASA FIRMS 检测数据呈现过去二十四小时内的活动火点。

太空任务图层提供滚动三十天内的发射活动，并带有载荷、级数与回收相关细节。

交通图层会在 OpenStreetMap 道路上模拟车辆运行。当配置 TomTom 后，实时流量速度能够驱动模拟，并呈现拥堵颜色。

公共交通图层覆盖公交车、有轨电车、地铁、火车与渡轮等内容，支持延迟回放、被选中车辆的轨迹以及不同交通方式对应的侦测标签。

共享单车图层呈现实时站点可用情况。

广播图层带来带地理位置的世界广播电台，并以模拟调谐器的方式让使用者在多个电台之间移动。

基础设施图层包括数据中心、水坝与海底电缆等捆绑静态数据集。

这些图层彼此并不相同。

有的展示移动目标，有的展示自然事件，有的展示基础设施，有的展示天气变化，有的则连接人与城市的公共信号。它们被放到同一个三维空间中，让世界不再只由行政边界、道路与地名组成，也由正在发生的活动、已被标记的设施与不断变化的环境共同构成。

公共摄像头被投射进三维城市

God’s Eye View 提供公共摄像头相关图层。

项目中提到，摄像头画面不是简单嵌入的网页窗口，而是被投射进三维城市空间中。使用者可以在多个区域查看公共摄像头相关内容，包括奥斯汀、得克萨斯州、加利福尼亚州、伦敦、安大略省、芬兰与特拉华州等。

这种呈现方式让摄像头不再只是列表中的一个入口。

它拥有空间位置。

当地球镜头不断靠近城市，公共摄像头与道路、建筑、交通和其他图层可以共同出现在场景中。使用者不只是知道某处存在一个画面，也能在三维环境中理解它与周边区域的关系。

项目还提供地图标注的车牌识别摄像头位置图层。这些位置来自 OpenStreetMap 贡献者的标记，按城市尺度视野加载，并只展示位置与标签信息。

在公共摄像头、街景、地形与交通共同存在的场景中，城市不再只是遥远的地理名称，而成为一处可以层层靠近、不断切换观察角度的空间。

从卫星云图到雷达回放，天气也成为地球的一部分

天气是 God’s Eye View 中极具动态感的一层。

项目支持动画化的十米预报风场，可使用 NOAA GFS 或 ECMWF IFS 数据，并可以叠加速度、温度或气压颜色场。使用者还能够在地图中心获取对应读数。

观测天气部分包括美国本土连续区域的降雨雷达、卫星云图与闪电密度信息。

卫星云图可以使用区域或全球红外云图。

闪电密度覆盖美洲与太平洋区域。

气旋图层则呈现大西洋以及东部和中部北太平洋地区的通告位置、预报路径与不确定性锥。

这些内容让天气不再只是某个城市天气卡片上的温度与图标。

它成为覆盖在地球之上的动态系统。风在流动，云在移动，雷达与闪电不断更新，气旋路径延伸到海面与陆地之间。对于一颗原本以实时飞机、船只与卫星为主角的地球而言，天气图层补上了另一种重要背景：世界并不是静止的舞台，环境本身也在持续变化。

语音不是遥控器，而是一种与地球对话的方式

God’s Eye View 支持通过实时 AI 代理进行免手操作。

使用者可以通过 GEV MIC 进入语音交互，并允许麦克风访问。语音能力可以使用 OpenAI API 密钥，也支持在同一台设备上选择实验性的已登录 ChatGPT 或 Codex OAuth 会话。

项目并不将语音仅仅描述为执行几个预设命令的遥控方式。

它强调，代理会在回答之前读取实时场景上下文，包括坐标、街道名称、当前启用的图层与视图比例。用户可以询问正在观看的城市，也可以选择飞机、船只或数据中心后询问对象信息，系统会结合对象实时遥测数据进行回答。

当镜头处在街道层级时，代理能够读取视口截图以识别可见的标识与建筑名称，并被要求不对标签进行虚构。

语音也可以用于镜头调度。

例如前往某座城市、围绕某个区域缓慢环绕、绘制路线、拉远到全球视图、切换视觉样式、启用图层、追踪目标、进入驾驶舱模式或重置地球，都可以成为与这颗地球交谈的方式。

它还可以承担分析式查询。

使用者能够询问特定区域上空的航班数量、驶向某地的船只、附近火情或特定高度范围内的飞行对象。项目中的分析回答会说明数据源是否陈旧，或是否正在使用备用数据。

这让语音不只是命令输入。

它更像一个站在实时地球旁边的助手，既能接受镜头指令，也能围绕当前场景回答问题。

在地球上做标注，像在现实表面铺开一块白板

God’s Eye View 提供语音白板能力。

使用者可以通过语音在世界上添加注释、真实边界多边形、标记与路线。也可以在界面中进入绘制功能，选择区域、线条或标记点，在真实世界上点击顶点，完成后为内容添加标签。

这让三维地球从观察工具变成可以被主动书写的空间。

一处区域可以被勾勒出来。

一条路线可以被画出。

一个地点可以被标记。

这些内容并不是漂浮在地图之上的临时涂鸦，而是被锚定到真实世界中。项目将这种能力称为覆盖在真实世界之上的白板，它使观察与表达可以在同一个空间内发生。

如果说实时图层让世界被读取，那么标注与路线则让使用者能够回应所看到的世界。

一键进入全球态势，也能一键回到整颗地球

面对如此多图层，God’s Eye View 提供 Global Context 模式。

它可以通过一次切换将全局态势组织起来，而当使用者离开该模式时，又可以回到原本精确的镜头视角。

这种设计适合在局部观察与全球视野之间切换。

有时，人们需要锁定一架飞机、一场火情或一个城市街区。

有时，又需要退回更高的位置，重新理解局部事件处在怎样的全球背景之中。

项目还提供 Reset Globe 功能。无论通过一个控制项还是一句语音指令，都可以回到完整地球视图。

这是一种非常简单的动作，却也体现了这套系统的核心节奏：深入观察，然后回到整体。

分享的不是截图，而是一段仍在继续的现场

God’s Eye View 支持分享链接。

镜头位置、视觉样式、已启用图层，甚至一个被追踪的目标都可以被序列化进链接之中。项目将实时目标形容为一次交接，而不是一枚静态书签。

这句话准确地说明了它与普通地图分享的不同。

当分享的是一个实时目标时，对方打开的并不是某一瞬间被冻结的画面，而是被带到同一个持续变化的观察入口。飞机会继续飞行，船只会继续航行，天气会继续变化，世界仍然在向前。

项目也支持可分享场景。

场景可以被导入、预览与分享，能够包含镜头锚点、编排好的镜头运动和数据包。场景导演功能则用于捕捉具有电影感的镜头巡游，适合制作片段与演示。

在这种模式下，地球不再只是一张信息面板。

它也是一处可以被编排的舞台。

从尼泊尔洪水回放，到火箭发射重建

God’s Eye View 不只呈现当下图层，也提供特定场景与事件回放能力。

项目中包含尼泊尔 Bhote Koshi 洪水场景，涵盖洪水路径、见证来源以及前后影像。README 对捆绑数据的非商业性质作出说明。

太空任务图层还能够呈现发射相关内容。项目展示了 Falcon 9 上升过程的重建估计，并明确将其标记为重建估计。使用者可以在不同播放倍率间切换，对发射过程进行查看。

这些能力让项目的地球不仅面向此刻，也能够容纳经过组织的事件叙事。

实时信号让使用者看见现在。

场景、回放与重建则让一些事件能够以更具路径感的方式重新展开。

不需要密钥，也能从基础地球开始

God’s Eye View 的启动门槛被设计得较低。

项目明确说明，使用者无需账户或 API 密钥即可启动应用。基础状态下可以使用 Esri 卫星影像与无需密钥的地形；当 Esri 不可用时，OpenStreetMap 可以作为备用底图。

在无需密钥的条件下，项目提供飞行、军用交通、卫星、地震、公共摄像头、广播与发射等能力。

对于需要更高层次视觉效果与额外能力的使用者，项目提供可选密钥配置。Cesium ion 令牌可用于符合条件的个人非商业使用场景，以获得 Google Photorealistic 3D 城市与世界地形。Google Maps 密钥可以用于直接获取 Google Photorealistic 3D、Google 地点搜索与街景相关能力。OpenAI 密钥则用于语音与 AI 抬头显示摘要。

这些密钥通过应用内的 POWER UP 面板添加。

项目强调，密钥属于能力升级，而不是启动前提。使用者可以先从基础地球与无需密钥的图层开始，再根据希望使用的能力逐步配置。

本地优先的运行方式

God’s Eye View 默认将服务器绑定在 localhost。

这意味着，默认情况下，其他人无法访问本地运行的实例。项目还说明，提供方设置面板只响应来自本机的请求。

当用户选择共享到局域网时，需要进行明确的主动配置。在共享模式下，提供方设置面板会被禁用，以避免远程用户访问密钥输入界面。

对于涉及私有密钥的 API，项目采用服务端代理处理，包括 OpenAI、AISStream、OpenSky OAuth 与摄像头帧等内容。README 提到，这一代理包含 SSRF 防护、响应处理与其他保护机制。

浏览器端密钥与服务端密钥也被区分处理。

Google Maps 与 Cesium ion 等浏览器端密钥需要在相应提供方侧进行限制。OpenAI API 密钥不会直接进入浏览器，客户端只会获得短时会话令牌。

这类设计与这颗实时地球的视觉冲击相比并不显眼，却构成了项目实际运行的重要底色。世界可以被点亮，但密钥不应随之暴露。

数据会延迟，也会不完整

God’s Eye View 的魅力来自实时感，但项目也对这种实时感保持清醒。

README 明确说明，大多数数据源是实时的或定期刷新的。交通是在真实道路上基于聚合位置数据进行模拟，公共摄像头姿态与火箭发射轨迹则属于粗略估计。

项目还强调，它是对公开与第三方数据的探索性可视化。数据可能延迟、不完整、经过建模、包含推断，或存在错误。

因此，它不应被用于飞行或海上导航、紧急响应、医疗或健康决策、投资决策，以及其他安全关键或运营关键用途。

这种边界让项目的定位更加明确。

它是一处用于探索、学习、观察与理解空间信息的开放画布，而不是一套经过强化的生产级决策系统。它可以帮助使用者看见世界中的许多动态，却不应被误认为世界本身的最终裁决。

用原生 JavaScript 搭建一颗可被阅读的地球

God’s Eye View 的技术组合并不追求复杂的框架叙事。

README 直接写出，它不使用框架，而是基于原生 JavaScript、CesiumJS 与 Vite 构建。Google Photorealistic 3D Tiles 用于地球呈现，OpenAI Realtime API 用于语音能力。

项目结构中，main.js 负责启动与图层注册，ui.js 承担运行时界面、面板、抬头显示与控制相关内容，hud.js 处理情报式 HUD 与 AI 场景摘要，keySetup.js 对应应用内密钥配置面板。

图层、数据模块、语音功能与场景导演功能也被分别组织。

每个图层都可以作为独立模块存在。

这与项目的整体理念相互呼应：先使用已有的公开数据源，再根据需要添加自己的图层。地球不是封闭成品，而是一块可以继续延展的画布。

它既可以被阅读，也可以被修改。

既可以被观察，也可以被扩展。

一颗开放的地球，一处不断生长的空间信息画布

God’s Eye View 的核心并不只是三维地球，也不只是飞机、船只、卫星与天气图层。

它真正试图构建的，是一种新的观看方式。

在这里，世界可以被缩放。

可以从全球层面理解，也可以落到一个街区、一条道路、一架飞机或一处摄像头附近。

可以通过鼠标与键盘操作，也可以通过语音下达指令。

可以切换成夜视、热成像与 CRT 风格，也可以回到最普通的地球视图。

可以追踪一个目标，也可以重置回整颗星球。

可以查看当下，也可以通过场景、路线、标注与回放组织自己的观察路径。

God’s Eye View 让公开空间信号拥有了共同的舞台。

飞机掠过天空，船只穿行海洋，卫星越过轨道，风场在大气中流动，云层与雷达不断刷新，城市中的交通、广播与公共摄像头共同组成地面世界的细节。

而站在浏览器前的人，拥有了一双能够不断拉远、靠近、追踪、询问与书写的眼睛。
