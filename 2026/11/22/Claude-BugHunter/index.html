岂能尽如人意，但求无愧我心！——林则徐

83 个技能，九次翻车：Claude-BugHunter 真正在补的是纪律

先说一个不太舒服的事实

安全这件事的瓶颈，很少是「不知道打哪」。

网上有无数清单：OWASP 前十、各种 payload 大全、公开报告的复现笔记、别人整理的绕过表。一个想入门的人，三天就能把术语背齐，一周就能把工具装完。

真正让人翻车的是另外一些事：还没验证就把草稿写了、截图里带着受害者的 Cookie、报告按错了平台的评级表、测试的时候把真实用户锁在门外、客户的安全团队在你眼皮底下把洞补了而你完全没察觉。

这些都不是知识问题。

Claude-BugHunter 的文档里有一节叫「为什么会有这个东西」。那一节没有讲愿景，列了九次具体的翻车。

这是我近期读到的、最不像产品文档的一段产品文档。

项目地址：https://github.com/elementalsouls/Claude-BugHunter

它是什么

一句话：一个给 Claude Code 用的技能包，做漏洞挖掘和外部红队。

描述里给了一串数字：82 个技能、15 个斜杠命令、覆盖 24 个核心漏洞类的 681 份公开报告提炼，外加企业身份与基础设施的攻击矩阵。

而正文里写的是 83 个技能，以及 681 条里有 433 条已经单独标注来源、可以逐条核对。

两个数字差了一个。这个后面再说，因为它挺有意思。

它的定位很明确：装一次，Claude Code 就不再是个聊天机器人，而开始像一个资深的漏洞挖掘研究员或者红队操作员——它知道技术、知道链式模板、知道平台的评级映射、知道卫生习惯，而且它待在范围里。

最后半句是重点。「待在范围里」这四个字，通常不会出现在一个攻击类工具的自我介绍里。

四层，但重心不在中间

整个包分成四层叠起来。

想。 两个技能：方法论和红队心态。前者是一套非线性的交战流程和批判性思考框架，后者是红队操作员的纪律。

打 Web。 58 个按漏洞类拆开的技能，从 681 份公开的 HackerOne 报告里蒸馏出来：每一类的检测模式、payload、绕过表、链式模板。

打边界。 企业平台的攻击链：M365 和 Entra、Okta、vCenter、SSL-VPN 设备、SharePoint、云 IAM。配的是 2024 到 2026 年的 CVE 链，以及拿到凭证之后怎么往上走。

交。 分诊验证、报告、证据卫生。这里面有那个「7 个问题的门」、按 VRT 定级、对「超出范围」判定的反驳、PII 打码、以及客户面向的红队交付物。

四层里，第一层和第四层是「怎么想」和「怎么交」，中间两层才是「怎么打」。

而市面上绝大多数安全提示词包，只做中间两层。

这也解释了它为什么值得看一眼：它把两头都做了，而且两头都比中间更用力。

那份「为什么存在」，是一份事故清单

回到开头那九次翻车。我把它按来源分了两组。

做漏洞赏金时暴露的四个缺口：

没有假设纪律。草稿在验证之前就写好了，浪费几个小时，还拉低了有效率。

没有按项目定制的报告战术。平台的默认评级把本该 P3 的发现自动降成了 P4。

没有交战协调。发现、证据、提交编号散落在不同文件夹里。

没有证据卫生。截图里漏出了 Cookie 和受害者的个人信息。

做外部红队时暴露的另外五个：

保守的默认值把真实发现撤回了。渗透测试的心态在有防守的目标上过早收手，而红队会继续往下走——绕过链本来可能就被找出来了。

没有交战中的态势感知。客户的安全团队在三十分钟内修掉了已确认的 SQL 注入；同一次实测里，外部攻击者锁掉了 14 个账户。 两件事在没有显式检测方法的情况下都是隐形的。

没有企业平台的攻击链。M365 加 Entra、本地 SharePoint、Cisco SSL VPN、vCenter、七个安卓 APK，全都需要 2024 到 2026 的 CVE 知识和平台专属手法。

没有客户面向的交付格式。漏洞赏金的报告模板套不进企业红队——那边要的是一份五十多 KB 的 Markdown 加 Word，里面嵌着截图。

没有拿到凭证之后的提权模型。侦察捞到了 AWS key、JWT、GCP 的 JSON，但说不清这些凭证给了什么权限、能往上走到哪。

九条。

请注意这九条里有几条是「知识缺口」——企业平台的 CVE 链、云 IAM 的提权路径，这些确实要学。

但另外几条全是行为问题。写草稿太早、评级选错、文件乱放、截图没打码、没意识到有人正在防守你。

而行为问题没法靠多读几篇文章解决，只能靠把正确动作写进流程，然后在流程里强制执行。

这就是为什么它里面有「7 个问题的门」，有一层专门叫证据卫生，有一个技能专门盯「交战中的事件响应迹象」。

一个技能包能做的事，本来就只有这一件：把老手脑子里的那些「别忘了」写下来，写到你没法跳过。

截图里漏掉的 Cookie

九条里，我最想单独说的是第四条。

做安全测试的人每天要截几十张图。请求、响应、报错页、后台界面、token、会话、用户数据。这些图要进报告，报告要发给客户或者平台。

而截图这个动作，会把你正在看的所有东西一起带走。地址栏里的 session、开发者工具里的 Authorization 头、页面上的真实用户手机号、测试账号旁边那个真实用户的订单号。

一次不小心的截图，等于把受害者的数据又泄露了一遍。而泄露的渠道，是你自己的报告。

文档对这件事的处理很具体：有一个专门的技能叫证据卫生，管 PII 打码；而在报告那一侧，还有一个叫「Bugcrowdninja 别名」的东西，以及「账号状态复原」和「友好测试者姿态」——后两样是用来向目标的风控团队证明你是合法测试的，不是来扫号的。

这三样凑在一起，说明作者想过一个很现实的场景：你在测试别人的系统，而别人的系统也在看你。

你的 IP 在日志里、你的账号在风控名单上、你的请求在 SIEM 里。你可以选择让那堆记录看起来像一个攻击者，也可以选择让它看起来像一个带着授权书的测试者。

这个区别，在出事的时候，就是「误会」和「立案」的区别。

58 个技能，681 份报告

中间那一层是数量最大的部分，也是最能说明「技能包」和「提示词包」区别的部分。

58 个按漏洞类拆开的技能，源头是 681 份公开披露的 HackerOne 报告，归到 24 个核心漏洞类里。文档还特意标了一句：其中 433 条已经单独标注来源，可以逐条核对。

这句话里最值钱的是「可以逐条核对」。

因为「从几百份报告里总结」这句话，如果不可核对，它就等于「我编的」。而一旦每条模式都能点回原始报告，它就变成了可审计的知识——你可以不同意它的归纳，但你能看见它从哪来。

它对这个做法的解释也很直接：Claude 知道的是真实审核员付过钱的那些链式模板，而不是抽象的 OWASP 前十。

这两者的差别很大。OWASP 前十告诉你「有 SSRF 这回事」；一份真实报告告诉你「某个看起来只负责预览的接口，其实能替你去请求别处，这条链被审核员认可并付了赏金」。

前者是目录，后者是路径。

而文档里还有一句关于生成方式的坦白：这些按类拆开的技能是用一个叫 public-skills-builder 的工具批量搭出来的，那个工具本身没有放进这个仓库。

用工具批量生成知识，然后把工具留在外面。这个选择意味着：仓库里躺的是产物，不是产线。产物可以审，产线你得自己重建。

边界写成了正文

这份文档里我最欣赏的一节，叫「范围」。

它先定义自己管什么：外部攻击面——任何能从互联网直接摸到、不需要先拿下内网端点就能碰的东西。

然后是「在范围内」那张清单：漏洞赏金、Web 应用渗透、外部红队、云配置错误与拿到凭证后的提权、侦察与开源情报、报告。

接着是另一半，标题里带了一句很硬的话：不在范围内，是刻意的，不是缺口。

它列了六类明确不做的事：

内部的 Active Directory 攻击——BloodHound、Kerberoasting、DCSync、Pass-the-Hash、AD CS 滥用那一套。理由是「不同的操作风险画像，需要不同的工具和判断」，并直接写「那是未来的另一个包，不是这个」。

C2 框架——Cobalt Strike、Sliver、Mythic、Havoc。理由是外部交战模型用不上。

后渗透、持久化、横向——从 Mimikatz 到黄金票据到计划任务。理由是「这些发生在边界已经被打破之后」。

规避——AMSI 绕过、ETW patch、杀软与 EDR 绕过。理由是「和上面的 C2 手艺绑在一起」。

iOS 渗透、硬件、射频、工控。

二进制利用、内核提权、浏览器内部。

然后是那句我愿意为它鼓掌的话：如果你在做包含 Kerberos 域接管链或者横向移动的内部红队，这个包在那些阶段帮不了你——而我们宁愿提前说，也不想让你在交战中途才发现。

「宁愿提前说」这句话，在安全工具里是稀缺品。因为安全工具最常见的营销方式是暗示自己什么都能干，而买家通常要到一半才发现不能。

它教你怎么跟模型的拒绝相处

这一节是我读完这份文档之后，认为最不像「仓库说明」的部分。

它先给了一段必须给的声明：这些技能是给你自己拥有的、或者有书面授权评估的资产用的——赏金项目范围内的资产、渗透测试的授权书、CTF、你自己的基础设施。

然后它讲了一件很少有人在文档里讲的事：

Anthropic 的模型有实时的网络安全防护，默认会拦下「漏洞利用或攻击性安全工具开发」。所以即便是授权的、范围内的合法工作，也可能撞上一次拒绝——而那次拒绝不是这个技能包造成的。

它给的解法不是「换个说法」，是去申请一个免费的项目：网络验证计划。做合法双用途工作的人，可以通过申请让防护针对这类工作做调整。而大规模数据外泄和勒索软件开发，仍然禁止，且不可调整。

接着是更细的一节，标题叫「为什么你的模型在会话中途换了」。

它说：在 Opus 5 上，有一小类高风险的网络安全请求——文档点名了漏洞利用生成、基于二进制的漏洞扫描、渗透测试——不会被拒绝，而是回落到 Opus 4.8。你会收到一个提示，回答也会标上实际作答的模型，但在一次很长的 agent 运行里，那个提示很容易被滚过去，于是看起来就像 Opus 5 悄悄变笨了。

然后它给了一张三行的表，三行对应三种真实处境：

如果你在审自己的代码——你就直说。防御性审查、按 OWASP 前十检查、为了修复而做的安全重构，这些描述是准确的，读起来就是修复。文档还补了一句：这不是绕路，这活本来就是防御的。

如果你在做授权的攻击性工作——这就是这个包存在的意义，而官方支持的路径是去申请那个计划。不要为了让分类器放行，把一次攻击性的交战重新措辞成防御性的。

如果你只是想把自动切换关掉——设置里的能力页可以关。

我看到中间那一条的时候，停了一会儿。

因为写这段话的人，本可以给一个更讨喜的答案。他可以说「遇到拒绝就换个问法」，那会显得这个包很能干。但他写的是：不要撒谎，去走流程。

这句话的代价是承认自己的工具有时会不好用。收益是——你读完这一段之后，会相信前面那八十三条技能里写的其他东西，也不是编的。

三条路装进去，各有各的代价

安装这件事，文档给了两条主路，加一条旁路。而它很老实地把三者的差别摊成了一张表。

插件。 在 Claude Code 里加一个市场、装一个包。八十三项技能和十五个命令全部以 claude-bughunter: 为前缀加载，跟着插件版本更新，你的 ~/.claude/ 里一个文件都不会多。

前缀这件事很实用。技能是按话题自动触发的，你机器上要是还装着别的包，同名技能就会打架。加个命名空间等于给它们分了姓氏。

代价是：命令行工具和那个交战用的脚手架，插件这条路给不了。

复制安装。 克隆仓库，跑一条脚本。技能和命令被拷进 ~/.claude/，同时把 hunt 这个交战脚手架接上。

好处是全套都有，坏处是你的目录被写进去了，更新得自己重新跑。

旁路：命令行。 那个叫 cbh 的终端 runner 是独立发布的，可以用 pipx 单独装，不需要克隆整个仓库。对已经用插件装了技能的人来说，这是补齐命令行最轻的办法。

这张表最值得看的地方，是它没有说「推荐插件」就完事。它明明白白写了：走插件，你得不到脚手架；走克隆，你的目录会被写。

一个安装章节愿意承认自己的推荐路径有缺口，比一句「三秒装完」有用。

装完之后的使用方式，倒是简单到不需要教程——用一句人话说明你在测什么，对应的技能自己加载：

没有命令名要记，没有参数表要查。这句话背后是一个设计判断：技能的入口不该是名字，是意图。

一个 SKILL.md，装到五个 harness

技术上，这个包赌的是一个很朴素的事实：技能就是 SKILL.md，而它是纯文本。

所以同一个知识层，能被五种宿主读：Claude Code 读 ~/.claude/skills/，OpenCode 读前一个目录和 ~/.agents/skills/，Codex CLI 读 ~/.agents/skills/，Hermes 读 ~/.hermes/skills/，Google AntiGravity 读 ~/.gemini/config/skills/。

装的时候一个开关就够：--all 会检测你装了哪些宿主，然后把技能复制到各自的路径；再加 --burp-mcp，顺手把 Burp 的 MCP 服务器接到每一家。

而它对这个能力划了一条很清楚的线：完整知识层可以移植到五个宿主，但斜杠命令和那个攻击面引擎，按设计只留在 Claude Code 里。

这条线划得很聪明。知识是可移植的，编排不是。因为斜杠命令、目录结构、状态机这些东西，各家宿主的实现差别太大，硬移植的结果就是五份都在半坏的状态。

先承认哪部分不能搬，比假装全都支持要专业。

路线图上还空着的那几格

这份文档有一节 Roadmap，用复选框列了八项。勾上的两项，剩下六项空着。

勾上的那两个也不是全绿：HackerOne 的 MCP 集成做完了，能做公开报告的重复搜索、项目统计和范围查询，还能可选登录读私有项目；行业专项技能只完成了一半，金融科技那个发了，医疗 FHIR 和政府合规两个还开着。

空着的六项，反而更能说明它现在缺什么：

按交战记忆的层。 跨目标记住那些模式——你在 A 项目踩过的坑，下次在 B 项目能想起来。

项目规则解析器。 从项目的规则文本里自动生成一份结构化的范围说明。

刷新那批挖掘技能。 用更新的公开报告重跑一次生成器。

补三个企业平台的深挖技能。 Citrix NetScaler、F5 BIG-IP、AD 证书服务。

把企业 VPN 的 CVE 矩阵按季度刷新，好跟上 2026 年的公告。

更新那张架构图，把企业平台那一层画进去。

最后这一项挺有意思：连画图的活儿都还欠着。

六项里，除了第一项算新功能，其余五项基本是「维护」——刷新、补齐、按季度跟、把图改对。

一个安全知识库最难的部分，从来不是第一次写出来，是让它别过期。CVE 会新增、平台会打补丁、公开报告的结论会被后来的分析推翻。而这份路线图敢把「按季度刷新」写成一条待办，说明作者知道这件事没有终点。

顺带说，文档里还有一处提到了维护节奏：CISA 的已知被利用漏洞清单覆盖情况，靠一个工作流模板每周刷新一次。

周更。这个频率比大多数安全内容的更新速度快一个数量级，而它只覆盖一个数据源。

两个数字对不上，和一句自我标注

现在说那个差一。

描述里写 82 个技能，正文写 83 个。而正文那张分类表我加了一遍：58 加 10 加 6 加 5 加 4，正好 83。

所以大概率是描述那边忘了改。

同一份文档里还有另一处：它说自己的流程是「六阶段的非线性工作流」，然后箭头里列了五个名字——侦察、测绘与排序、狩猎、验证、报告。

六个，数出来五个。

第三处更隐蔽一点。技能分类表里，企业平台那一类是 10 个；而路线图里那条待办写的是「把 7 个技能的企业平台层画进架构图」。

十和七。

三处加在一起，画出的画像很清楚：这是一份跟着代码一起长的文档，改得比同步快。

这种小裂缝在一个 83 个技能、九次交战的仓库里，说实话不致命。刚更新完技能、忘了同步一行描述，是所有快速迭代的项目都会发生的事。

但它值得记一笔，因为它和另一件事形成了很有意思的对照。

同一份文档里，那个演示用的对话记录下面，有一行很小的字：上面那个块是示意的转录。 想录一段真实的演示，用 asciinema 录下来传到官网，然后把徽章贴这儿。

一份文档，一边把「82 还是 83」这种数字写错了，一边主动承认自己的演示是编的、还教你怎么录一段真的。

这两件事放在一起，反而让人放心。因为这说明第二种诚实不是包装出来的姿态，是习惯；而第一种错误，就是单纯的手滑。

分寸感藏在安装脚本里

还有两个细节，属于「不写也没人会发现，但写了说明想过」的那一类。

第一个：它有一个姊妹项目，做侦察阶段的技能，这个包接着往下做。而两边共用两个技能，且那两个技能是以这边为准、往那边同步的。

于是就有了一个很实际的问题：两个都装，会不会互相覆盖？

文档的回答是：两个包的安装脚本都会记一份清单，遇到完全相同的技能就跳过不复制；而卸载时，--uninstall 会保留另一个包仍然拥有的技能。

也就是说，卸载其中一个，不会把另一个弄坏。

这个设计要花多少功夫？大概是几十行脚本。但它省掉的是用户一次「我的技能怎么没了」的深夜排查。

第二个：安装时它会问你要 HackerOne 的 API 用户名和令牌。文档紧接着说，这两个只用来让 MCP 读你的私有项目和自己的报告，不需要就留空。而公开的那些工具——重复报告搜索、项目范围查询——不填也能用。

先把「可以不给」说清楚，再讲给了有什么用。这个顺序，决定了有多少人会在第一步就关掉窗口。

许可切成两半

最后是许可，切得很干净。

代码——Python 辅助脚本、shell 脚本——走 MIT。

内容——技能方法论、字典、正则目录、定级细则、文档——走 CC BY 4.0。

这个切法不是形式主义。因为这个仓库里真正值钱的东西，恰恰是「内容」那一半：由 681 份报告蒸馏出来的模式、按类的绕过表、企业平台的链式笔记。这些是文字，不是代码，用软件许可去套它们本来就不合身。

另外还有一份 NOTICE，管上游技能的归属，以及一条不再分发的说明。

把「代码」和「文字」分开授权，是一家知道自己卖的是什么的项目才会做的事。

最后

回到那九次翻车。

一个技能包能教会模型的东西，其实很有限。它教不会判断力，也教不会那种「这里不对劲」的直觉——那东西只能靠几百个小时的实操长出来。

但它能教另外一些东西：验证之前别写草稿、报告之前先过七个问题、截图之前先看有没有别人的数据、测试的时候记得有人在看日志、交战的第一个回合就把授权范围说清楚。

这些听起来都不高级。可它们恰好是每次翻车的真正原因。

所以这份文档里最动人的不是那 681 份报告，是那句「截图里漏出了 Cookie 和受害者的个人信息」。

能让一个人把这条单独拎出来、写成一个技能，通常是因为他见过那个不该出现在报告里的会话令牌。

八十三条技能，是从那儿开始长的。
